# 12. ステータス色の再調整（R-159）

## 1. 目的

状態の緊急度と色の目立ち方を一致させる。未整理の `inbox` は次に判断すべき対象として緑で示し、`todo`（表示名「後日着手」）は中立的なグレーにする。`someday`（表示名「いつかやる」、発注者の言う「あとでやる」）は黄色にする。期限超過はステータスとは別の注意情報として淡い赤で示す。

**2026-08-29 仕様訂正**: 初版でCodexが「`someday`をグレーにする」と実装したが、これは発注者の言う「あとでやる」がどのステータスを指すか確認せずに進めた誤り。発注者への確認の結果、発注者原文の「あとでやる（緑色に見えていたもの）」は実際には `todo`（後日着手、既存色teal。全体一覧の`StatusDot`で緑がかったteal色の大きめドットとして表示されており、添付スクリーンショットの緑っぽいドットと一致）を指しており、`someday`（いつかやる）は別途「黄色」に変更する、という発注者指示に基づき本書を訂正した。

## 2. 対象

- 全体一覧、状況把握、グリッド、ガント、フローチャートなど、共通のステータス色または期限状態色を表示する箇所
- 共通コンポーネント・共通色決定関数がある場合はそこを正本とし、画面ごとの色分岐を増やさない
- データモデル、API、DB、ステータス遷移は変更しない

## 3. 色の意味規則

| 表示対象 | 変更後 | 規則 |
|:--|:--|:--|
| `inbox` | 淡い emerald 系の緑 | 未整理・要判断の入口を示す |
| `todo`（後日着手、発注者の言う「あとでやる」） | グレー | 目立たせず、中立的な保留状態として示す。旧色teal（緑がかった色）から変更 |
| `someday`（いつかやる） | 黄色（amber系） | 旧色purpleから変更。発注者指示による |
| 期限超過 | 淡い赤 | 有効な期限が超過した対象を、強すぎない警告色で示す |

期限超過の判定は既存ロジックを変更しない。ステータス色と期限超過色が同じ表示要素で競合する既存箇所では、期限超過色を優先する。`focus`、`confirmed`、`waiting`、`pending`、`done` など、上表にない状態の色は変更しない。

## 4. 実装原則

- 色の決定を共通化できる既存箇所を調査し、最小の変更で全対象画面へ反映する
- 色以外のサイズ、余白、配置、文言、操作、アニメーションは変更しない
- dark mode が既存定義に含まれる場合は、同じ意味規則を保つ対応色を設定する
- 色だけに依存して状態名を失わせない。既存のテキスト、title、aria情報は維持する

## 5. 受け入れ条件

1. `inbox` が淡い emerald 系の緑で表示される
2. `todo`（後日着手）がグレーで表示される
3. `someday`（いつかやる）が黄色で表示される
4. 期限超過が淡い赤で表示され、同一表示要素で競合する場合はステータス色より優先される
5. 対象画面で上記規則が一貫し、該当しないステータス色（focus・confirmed・waiting・pending・done等）は変わらない
6. 色以外のレイアウト・操作に回帰がない
7. 対象テスト、フロントエンド全テスト、TypeScript型チェック、ビルドが通る
8. 変更前後のスクリーンショットまたは同等の視覚確認でレイアウト崩れがない

## 6. 検証

- 共通色決定ロジックの単体テストで `inbox`、`todo`、`someday`、期限超過、変更対象外ステータスを確認する
- 共通ロジックを使わない表示箇所が残る場合は、対象コンポーネントの描画テストを追加する
- `npm.cmd test -- --run <対象テスト>`
- `npm.cmd test -- --run`
- `npx.cmd tsc --noEmit`
- `npm.cmd run build`
