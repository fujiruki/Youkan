## 2. 各機能の詳細

### F-01: アイテム管理

アイテムはタスクとプロジェクトの総称。すべてitemsテーブルに統一保存される。

**アイテムが持つフィールド:**
- タイトル、メモ、ステータス
- 納期（due_date）、マイ期限（prep_date）
- 目安時間（estimated_minutes）、目安日数（work_days）
- 所属会社（tenant_id）、担当者（assigned_to）
- 所属プロジェクト（project_id）
- ドメイン区分（private / business）
- アーカイブフラグ（is_archived）、削除日時（deleted_at）

**プロジェクト化:**
- `is_project = 1`でプロジェクト化
- 子タスクは`project_id`で親プロジェクトに紐付く
- プラグインの作用でフィールドを増やす仕組みあり

### F-02: ステータス管理（拡張: R-028）

詳細は [04_データ設計.md](04_データ設計.md) の状態定義を参照。

アイテムは8つの状態を持つ（正本は `04_データ設計.md` §4.1）:

| 状態 | 説明 | キャパシティ計算 |
|---|---|---|
| `inbox` | 思いつき投入直後（未判断） | 含む |
| `todo` | 後日着手。やると決めた順番待ち（今日はやらない、人待ち・条件待ちでもない）（R-125） | 今日のキャパ: **除外**／日付別集計（ガント・カレンダー）: 含む |
| `focus` | 今日やる／集中対象 | 含む |
| `waiting` | 人待ち（返信・納品・他者の判断・決裁・入金待ち等） | 含む（待ち時間として） |
| `pending` | 条件・時期待ち、または判断保留。`pending_condition`/`review_date`を持てる（R-125） | 含む |
| `someday` | いつかやる（自分の意志で寝かせる、期限なし、義務感なし） | **除外**（やる気を圧迫しない夢リスト） |
| `done` | 完了 | 集計のみ（実績） |
| `cancelled` | 断った（R-124） | 集計のみ（実績） |

**基本フロー（本道: inbox → todo → focus → done）:**
1. **発生**: `inbox`（思いつきをInboxに投入）
2. **判断**: inbox → todo / focus / waiting / pending / someday / done / cancelled
3. **選定**: todo → focus（今日やるものを順番待ちから選ぶ）
4. **実行**: focus → isEngaged: true（実行中）→ done（完了）

#### 状態遷移ルール
- `inbox → someday`（判断結果として「寝かせる」）
- `someday → focus`（やる決断、希望日入力可）
- `someday → done`（やらないと決めた）
- `someday → inbox`（再判断したい）
- `pending → someday`（外的要因待ちを解除して自発的延期に変換）

#### pending と someday の差別化（必須要件）
- `pending` = **外的要因待ち**（自分は動けない）：⏸ アイコン、amber 系
- `someday` = **自発的延期**（自分が動かないと決めた）：💭 アイコン、purple 系
- ラベル文言: 「保留（外的要因待ち）」「いつかやる（自分で寝かせる）」

#### キャパシティ計算からの除外（Youkan独自の差別化軸）
`someday` 状態のアイテムは QuantityEngine の集計対象外。これにより「やる気を圧迫しない夢リスト」として静かに存在する。

**完了日の記録:**
- ステータスが `done` に変更された瞬間に `completed_at` を記録する
- `done` から他のステータスに戻した場合は `completed_at` を NULL にリセットする
- `completed_at` は量感カレンダーで「この日に何を完了したか」を振り返るために使用する

### F-03: Quick Input

Stream View上部に配置される高速入力欄。
- 思いついた瞬間にタイトルだけでInboxに放り込める
- `Ctrl+I`でフォーカス
- 「考えながら入力しない」ための0秒投入口

### F-04: 判断詳細（Decision Detail Modal）

すべてのViewから呼び出し可能な「判断のための個室」。

**表示内容（順序厳守）:**
1. **判断対象**: アイテム名と判断内容
2. **判断材料**: 納期・マイ期限（ここで初めて表示される）、想定日数等
3. **選択**: Yes（今日やる）/ Hold（今は決めない）/ No（見送る）

**ルール:**
- 納期・残日数はこのモーダル内でしか見えない
- 赤色・警告アイコン禁止。「あと○日」表現禁止
- 確認ダイアログなし（ボタン一発確定）
- 戻る = 未判断

**左カラム量感カレンダー（R-061〜R-063）:**
- Google 外部イベントと進捗バー（CapacityBar）を表示（§5.6.12 参照）
- 密度トグル（FULL/COMPACT）でカレンダーの表示サイズを切替。`localStorage` に永続化
- 量感ヒートマップの母集団は左上フィルタ（全て/個人/会社）と同等。開いているアイテムの所属プロジェクト/テナントによる絞り込みは行わない（§5.6.13 参照）
- 外部イベントチップは時刻を非表示にし `📅 タイトル` のみ表示（§5.6.14 参照）
- 詳細内カレンダーは入力補助のための埋め込み部品であり、スクロール中は通常カレンダー用の範囲拡張・表示月同期・セル装飾トランジションを抑制し、即時追従を優先する

**スマホ向けレイアウト（R-064）:**
- 詳細は §6.1.1 参照。横画面（高さ ≤ 500px）では2カラム化、縦画面ではカレンダー下に独立スクロール領域

### F-05: Morning Planning（朝の段取り）

focusステータスのタスクの実行順序をドラッグ&ドロップで並べ替える機能。

**思想:**
- システムは「この順番でやるべき」とは言わない
- 「今日focusに入っているタスクはこれだけです」と事実を提示する
- ユーザーが自分でドラッグして順番を決める

**実装:**
- Stream ViewのNext Strategyセクションが対象
- `@dnd-kit/core` + `@dnd-kit/sortable`使用
- 並べ替え完了時に`POST /items?action=reorder_focus`で`sort_order`を自動保存
- ソート: `sort_order ASC` → `updated_at DESC`（フォールバック）

### F-06: 量感カレンダー

日別の忙しさをヒートマップ（色の濃淡）で可視化するカレンダー。

**表示ロジック:**
- 各日付のキャパシティ（MAX値）に対するタスク合計時間の割合で色を決定
- 薄い色 = 余裕あり、濃い色 = 満杯、さらに濃い色 = 超過

**目安期間の算出（Backwards Allocation）:**
1. 基準日（納期 > マイ期限の優先順位で決定）から過去へ遡る
2. 稼働日のみ工数を消化（休日・キャパ0日はスキップ）
3. 消化した日付を「青枠」で描画

**操作:**
- 日セルをシングルクリック → 背景色に影響するタスクへ曲線で指示
- 日セルをダブルクリック → 影響タスクの一覧表示
- アイテムカードをクリック → 影響するセルが光る

**完了タスクの表示（振り返り機能）:**
- カレンダーの各日付セルで、その日に完了したアイテム（`completed_at`がその日のタイムスタンプ範囲内）を確認できる
- 「この日に何をしたか」を振り返る用途

**キャパシティの分母（フィルタ連動）:**

| 場面 | 分子 | 分母 |
|:--|:--|:--|
| 個人×プライベート×全て | 自分の全アイテム | 業務キャパシティ合計 |
| 個人×プライベート×個人 | 個人タスクだけ | 個人キャパシティ |
| 個人×プライベート×会社 | 会社タスクだけ | 会社キャパシティ |
| 個人×会社モード | A社タスク全件 | 主力社員のA社キャパ総和 |
| 会社×社内モード | domain:privateタスク | 社員キャパ集計 |
| 会社×会社モード | domain:businessタスク | 社員キャパ集計 |

**分母の確定ルール:**
- 個人アカウントのプライベートモードでは、分母はログイン中の本人がその日に使える時間を基準にする
- 「全て」は本人の業務キャパシティ合計を使う。所属会社ごとのキャパシティを足し上げない。同じ人の時間を二重計上し、忙しさが薄く見えるため
- 「個人」は、業務キャパシティ合計から明示された会社キャパシティ合計を差し引いた残りを使う
- 「会社」は、本人が各社に明示配分した会社キャパシティの合計を使う
- 「A社 / B社」などの個別会社は、その会社に明示配分したキャパシティを使う
- 会社配分が未設定の会社は 0 分として扱う。総キャパシティへフォールバックしない
- 個人アカウントの会社モード、および会社アカウントの社内/会社モードでは、分母は対象会社の主力社員がその会社へ配分しているキャパシティの総和とする
- 会社全体の分母は、`memberships.is_core = 1` のメンバーについて、`memberships.capacity_profile`（曜日別・日別例外・会社別配分）から日別キャパシティを算出して合計する。`capacity_profile` 未設定時は `memberships.daily_capacity_minutes` を使う

**進捗棒グラフ（R-034 Phase 1, R-035）:**
- 各日付セルの下端に高さ 4px のプログレスバーを描画
- 単色（落ち着いた緑系、`emerald-500` 想定）。100% 超で `red-500` に切替
- 棒グラフは「進捗の意味」を持つ。未完了部分=濃色（`emerald-500`）、完了部分=淡色（`emerald-200`）の2層構成
- 数値表示なし、ホバーツールチップなし（即時性優先）
- 量感計算には完了アイテム所要時間も含める（分子）。完了量を可視化することで「今日は何 % 進んだか」が直感的に把握できる
- 対象: グリッドビュー必須、ガントビュー一覧表示にも適用

### F-11: キャパシティ管理

- テナント別の週間パターン設定（曜日ごとの稼働時間）
- 日次例外オーバーライド（祝日だが稼働、体調不良で早退等）
- キャパライン: focusキューの累積時間がDaily Capacityを超えた地点に赤線

#### 日次キャパの決定規則（R-130で一本化）
ある日の個人キャパ（分）は次の優先順で決まる。**この規則を実装する関数はフロント `logic/capacity.ts` の `getDailyCapacity(date, config)` ただ1つ**で、`QuantityEngine`（ガント日付ヘッダー・量感・逆算配分）、週の残量（R-128）、最遅着手日（R-129）はすべてこれを呼ぶ。バックエンド `QuantityService::getDailyCapacity` も同じ規則で実装する。

1. 日別例外 `exceptions[YYYY-MM-DD]` があればその値（0＝休み）
2. 曜日パターン `standardWeeklyPattern[曜日]` に**その曜日の値**があればその値（0＝定休日）
3. `holidays`（weekly指定）に該当すれば0
4. 1〜3で値が決まらず、その曜日が土日なら0（既定の週休2日。曜日パターンに平日しか保存されていない既存データでも土日は休みのまま）
5. それ以外は `defaultDailyMinutes`

- 個人設定の「定休日・祝日設定（Advanced JSON）」欄（`users.non_working_hours`）は形式未定義でどこからも読まれていなかったため**廃止**（UIから削除。カラムは残す）。定休日は曜日パターンで0にする
- 個人設定のキャパ欄に上記規則の説明文を1〜2行表示する（「曜日パターンで0＝定休日。未設定なら土日休み。日別例外が最優先」）

### F-18: 親→子孫カスケードの一般則

Youkanでは `parent_id` / `project_id` で表現される階層において、親アイテムへの操作は配下の子孫すべてに自動伝播する。

#### 対象操作と伝播内容

| 操作 | 子孫への伝播 |
|---|---|
| テナント変更（`tenant_id` 更新） | 子孫の `tenant_id` を移動先に揃える |
| プロジェクト変更（`project_id` 更新） | 子孫の `tenant_id` のみ追従（`project_id` 構造は保持） |
| アーカイブ（`is_archived = 1`） | 子孫も `is_archived = 1` |
| ゴミ箱（`deleted_at = ?`） | 子孫も同様 |
| 復元（`is_archived = 0, deleted_at = NULL`） | 子孫も同様 |
| 物理削除（`DELETE`） | 子孫も物理削除 |

#### 親子関係の判定

`is_project` の値に依存しない。`parent_id` または `project_id` で参照される全ての子孫が対象。
これにより、通常タスク（`is_project=0`）の親をアーカイブした場合も、その子subtaskは連動して非表示になる。

#### 権限チェック

テナント変更時、移動先 `tenant_id` がユーザーの `joinedTenants` に含まれていなければ HTTP 403 を返す。
これにより未所属テナントへの越境転送を防止する。

### F-24: フローチャート操作性・軽量化（R-074）

### F-53: 今週の残量1行と登録時の一言（R-128）

- **背景**: R-126会議の採用案C。「まだ余裕がある」判断で開始を先延ばしし、その度に1本足してしまう構造に対し、**足そうとした瞬間**に今週の残量を数字で返す。常時バーの新設はしない（量感画面が使われなかった実績）。既存ヘッダーの「Reality (Total Load) 123/480 min」（7px英字、読まれていない）を日本語1行に置き換える
- **週負荷の定義**（フロント・バックエンドで同一の式。複雑な逆算配分はしない）:
  - 週: 今日〜今週の日曜（週の始まりは月曜）
  - `capacity_minutes` = 今日〜日曜の各日の日次キャパの合計（既存キャパ設定: `daily_capacity_minutes`／曜日パターン／日別例外／休日0）
  - `need_minutes` = 未完了（`status ∉ {done, cancelled, someday}`、`is_project=0`、未削除・未アーカイブ）かつ有効締切（`due_date`/`prep_date`の早い方）が今週の日曜以前（期限超過分も含む）のアイテムの `estimated_minutes` 合計。目安未入力は0として数える（水増ししない）
  - `shortfall_minutes` = `max(0, need − capacity)`
  - `over_candidates` = `need_minutes` に含まれるアイテムのうち有効締切が遅い順に最大2件（後ろにずらしやすいもの。直近に作成・更新した本人は除く）。`{id, title, deadline, estimated_minutes}`
- **ヘッダー1行**: 既存「Reality (Total Load)」ブロックを置き換え、`今週 必要 Yh ／ 枠 Xh` の日本語1行。不足時のみ末尾に赤字で `Zh足りない`。バーは残してよいが色は不足時のみ赤。値はフロントで全アイテムから算出（既存の `CAPACITY_UPDATE` と同じ疎結合パターンで送出）。スマホヘッダーは非表示のまま
- **登録時の一言（画面）**: 新規登録・期限や目安の変更の直後に `shortfall_minutes > 0` なら既存Toastで1回だけ `今週 Zh足りない。外す候補: A(8/22, 3h)／B(8/23, 4h)` を表示。判断UI・確認ダイアログは付けない（1タップ増やさない）
- **登録時の一言（番頭）**: `POST /items`・`POST /integrations/inbox`・`PATCH /items/{id}`（`due_date`/`prep_date`/`estimated_minutes` のいずれかを含む更新時）のレスポンスに `week_load: {capacity_minutes, need_minutes, shortfall_minutes, week_end, over_candidates}` を同梱する。同じ値を `GET /quantity/week` でも返す。番頭は不足時のみ「今週Zh足りない。外す候補: A／B。どれか、または『そのまま』」と1問だけ返す（番頭側の運用）
- **前提**: 1日の実働は既存のキャパ設定（個人設定の日次キャパ・曜日パターン・日別例外）を使う。R-128 実装時に設定UIが実用に耐えるか確認し、致命的な不備があれば報告する（新設はしない）
- **やらないこと**: 新しいバー・新画面／安全係数（R-129で別途）／登録のブロック／評価語

## 補足: `focus` / Today / focusedProject の区別（2026-07-07）

Youkan では `focus`、Today、focusedProject は別の軸として扱う。

- `status = focus` はアイテムの状態である。「やる判断済み」「実行候補に上がれる」「日程・量感の対象になり得る」ことを表すが、それだけでは Today に入ったことを意味しない。
- Today は当日の実行キューであり、実装上は `executionItem`、`todayCommits`、`todayCandidates` で表現する。Today に入ったものだけを「今日の約束」として扱う。
- Today 上のアイテムは多くの場合 `status = focus` だが、`status = focus` の全アイテムが Today 上にあるわけではない。`focus` だが Today ではないアイテムは、全体一覧・ガント・量感カレンダーでは未完了の有効アイテムとして扱う。
- `focusedProjectId` / `activeProject` は表示・入力・量感計算のプロジェクト文脈である。`status = focus` や Today とは無関係の軸で、特定プロジェクト配下の表示、インライン追加時の所属継承、量感カレンダーの母集団絞り込みに使う。

したがって、「focus であること」「Today にいること」「focusedProject の文脈で見ていること」を同一視してはならない。
