## 2. R-0164 サブプロジェクト2行重複＋表示タイミング

### 2a. 2行重複
- 症状: Beaver連携プロジェクト配下のサブプロジェクト（見積行単位）が全体一覧で各2行表示される
- 原因未確定。実装Agentは最初に**本番DBを読み取り専用で調査**する（`external_work_package_links` の同一案件・同一labelの重複、`items` の `is_project=1` の同一案件件数、header行とitem行の二重描画）。書き込み・削除は禁止
- 調査結果に応じて `BeaverSyncService.php`（重複生成の防止）または `hierarchy.ts`/描画層（二重描画の除去）を修正。既存の重複データが本番にある場合の掃除方針は、Agentが指揮AIへ確認してから決める（勝手に本番データを削除しない）
- 受け入れ条件: 1つの見積行につきサブプロジェクト行は1行のみ
- **根因（本番DB読取調査で確定）**: 重複ではなく仕様通りの2件。Beaverは1見積行につき `factory`/`site` の2つのwork_package（`beaver:voucher:X:line:Y:factory` / `...:site`、同一`source_line_id`・同一label）を返し、`upsertWorkPackage` が各々を別itemにしていた。`external_work_package_id` の重複や同一IDの二重登録はなく、`youkan_item_id` の重複もなし。描画層（hierarchy.ts）の二重描画ではない。全体一覧では同名のため2行が同じに見えていた
- **発注者判断（確定）**: 統合はせずラベル区別とする。ラベルは見切れない固定幅の短縮バッジ: work_package の header 行で案件名の**前**に置き、工場→「工」（青系）、現場→「現」（橙系）、未知値は先頭1文字（グレー）。`title` 属性に正式名、`shrink-0` で省略・見切れさせない（ダークモード対応）。省略されるのは従来通りタイトル側（truncate）のみ
- **修正（表示層のみ・データ非変更）**: 全体一覧のwork_package header行に工場/現場ラベル（`workPackageCategoryLabel`：factory→工場、site→現場、未知値はそのまま）を表示し、2行を区別可能にする（08_Beaver連携Y2.md §9「categoryは表示用ラベル」に沿う）。Beaver側の分割単位・同期モデルは変更しない。「1見積行=1行」へ統合する案（同期モデル変更・既存データ移行が必要）は指揮AIの判断待ち

### 2b. Beaverから開いた直後にサブプロジェクトが出ない
- 原因（調査済み）: `useBeaverIntegration.ts` はマウント時に `BeaverApi.sync('diff')` を実行するが、同期後に viewModel（gdb*/allProjects）を再取得しないため、同期で新規作成されたwork_package itemが次の再取得（タスク作成等）まで表示されない
- 仕様: 同期完了後、created/updated が1件以上のときに一覧を1回再取得する
- 受け入れ条件: Beaverリンクから開いた直後にサブプロジェクトが表示される
- 実装: `useBeaverIntegration(onSynced?)` が初回 `sync('diff')` の `created`/`updated` が1以上のとき `onSynced` を1回呼び、`OverviewBoard` は `viewModel.refreshGdb()` を渡す
