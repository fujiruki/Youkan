# 17 改善要望4件バンドル2（R-0167〜R-0170）

## 1. R-0167 全体一覧「＋」追加時の404

- 症状: 全体一覧のプロジェクト右の「＋」でアイテムを追加すると、`Creating item` の後に別アイテム（`019f3bed-…`）への `Updating item` が走り、`backend/index.php/items/019fea80-…` が404（`Item not found or access denied`）。以降のアイテム作成は続行できている
- 原因未確定。実装Agentは根本原因を調査（追加処理の呼び出し経路、更新対象IDの由来、そのIDが本番に存在しない/テナント違い/削除済みの可能性）。本番DBは**読み取り専用**でのみ調査可。対症療法（例外の握りつぶし）は禁止
- **根因（確定）**: 404の対象 `019fea80-…` は新規作成アイテムではなく、同プロジェクト配下の**ゴミ箱内（`deleted_at` 設定済み）の子アイテム**（本番DBをSELECTで確認）。直前の `Updating item 019f3bed-…`（親プロジェクト）のレスポンス `affectedDescendantIds`（`getAllDescendantIds` は削除済みも含む）を `useYoukanViewModel.refreshItems` が `ApiClient.fetchItemsByIds` で再取得し、`GET /items/{id}`（`show()` は `deleted_at IS NULL` 限定）が404となる。`fetchItemsByIds` は失敗を `catch(() => null)` で許容する設計だが、`request` が非silentのため全体エラートーストが出ていた。加えて `request` のGET重複排除で `fresh.finally(...)` の派生Promiseが未処理拒否（`Uncaught (in promise)`）になっていた
- **修正**: `fetchItemsByIds` を silent（404はスキップ、トースト無し）にし、GET重複排除の派生Promiseの未処理拒否を吸収（呼び出し元への拒否伝播は不変）。テスト `api/__tests__/client.fetchItemsByIds.test.ts`
- 修正後も、エラー文言はユーザーに分かる日本語で表示されること（既存の共通エラー表示に従う）
- 受け入れ条件: 「＋」で追加しても404が出ない。追加したアイテムが期待どおり親プロジェクト配下に作られる

## 2. R-0168 ガント月移動

調査結果（静的追跡）。対象画面は `VolumeCalendarScreen`（`RyokanCalendar`/`RyokanGanttView`/`CalendarHeader`）。
- A（確度高）: 表示列は今月±2ヶ月のみ。矢印で範囲外の月へ出ると、`RyokanCalendar.tsx` の pendingScrollTarget 消費が範囲拡張後・`allDays` 更新前に走り、スクロールが空振りして列だけ入れ替わる。ラベルも誤った月に書き換わる
- B（確度中〜高）: `RyokanGanttView.tsx:475-478` のラベル月判定が左固定列256pxを考慮せず、中央日付が約11〜16日後ろにずれる。月後半で翌月ラベルになり、次の「次月」で1ヶ月飛び越す。`scrollToDate`（:455-472）も同様
- C（確度中）: クリック直後のcurrentDate更新・pendingScrollTarget・250msデバウンスの `handleVisibleMonthChange` が競合
- D（確度低）: 「今月を表示」も範囲外で空振りしうる。Bによる誤ラベルで `isCurrentMonth` により押せなくなる

修正方針:
- A: pendingScrollTargetの消費を「対象日の `data-gantt-date` 要素がDOMに存在する」ことを条件にする。range拡張とスクロールを一本化し、focusDate由来のrange再生成との二重管理を解消。初期スクロールも「対象要素が実在したときのみ完了扱い」
- B: ラベル算出で固定列256pxを補正（または `data-gantt-date` 要素の実位置から中央日を求める）。`scrollToDate` も同様
- C: 矢印クリック起点のプログラムスクロール中は `handleVisibleMonthChange` の反映を抑止する
- D: A・Bの修正後に「今月を表示」が範囲外でも動くことを確認
- グリッド/タイムライン表示は別実装。共通の `scrollToDateElement` を変える場合は回帰を確認

受け入れ条件: 今月から次月・前月を6回ずつ押して、毎回1ヶ月ずつ進み、押すたびに該当月が画面中央に表示され、ラベルとスクロール位置が一致する。「今月を表示」で範囲外からも戻れる。速い連打でも最終的に矢印で指定した月に収束する。
テスト（Red先行）: ①範囲外月への `scrollToMonth` でscrollToがleft>0で呼ばれる ②ラベル算出（colWidth 16/24、固定列256px込み） ③次月4回でSep→Oct→Nov→Dec→Jan

## 3. R-0169 ガントの非表示タスク

- 仕様: 全体一覧がR-0162（`15_Beaver標準事務タスク再設計.md`）で除外している「計算には入れるが表示しない」タスク（`generatedTaskRole==='invoice' && status==='pending'` 等、実装の除外述語）を、ガントチャートでも同じ規則で非表示にする。**除外述語は全体一覧と共通化して再利用**し、ガント側に条件を複製しない
- 容量計算（capacity）には引き続き含める（表示のみ除外）。ガント以外のビュー（グリッド/タイムライン/フロー等）で同種の漏れがあれば調査結果として報告（今回の修正範囲はガントのみ）
- 受け入れ条件: Beaver標準タスクの請求（未納品でpending）がガントに出ない。納品済み以降で全体一覧に出る状態ではガントにも出る。容量計算は変わらない

- 対象: `OverviewBoard/OverviewItem.tsx` の `data-testid="overview-beaver-badge"`（現状は行右寄せの「B」）
- 仕様: バッジを案件名の**先頭**（フォルダアイコンの直後、名前の前）に移動。「◯の中にB」の背景透過SVGアイコン（`currentColor` で今のBと同じ色、今と同じ大きさ）に置き換える。R-0165の得意先名・R-0164の「工」「現」バッジと並びが崩れないこと
- 受け入れ条件: Beaver連携プロジェクト行で、先頭に丸囲みBアイコンが出る。右寄せのBは無くなる。`overview-beaver-badge` のtestid・クリック挙動（あれば）は維持
