# 11. 全体一覧ドラッグ範囲拡大

- 要望: R-157（`docs/requests_log.md`）
- 前提: 09（`docs/SPEC/09_全体一覧ドラッグでプロジェクト移動.md`, R-155）・10（`docs/SPEC/10_全体一覧Beaver連携バッジ.md`, R-156）は無変更。本書はその上に積む追加仕様であり、09の不変条件・§6所属変更の値の決め方・§7バックエンド検証・§8保存フロー・§9 Undo・07/08のBeaver連携仕様をすべて継承する
- 対象画面: 全体一覧（`OverviewBoard.tsx` / `OverviewItem.tsx`、Newspaper View）

## 1. 目的

R-155の初版では、ドロップ可能な範囲がプロジェクトのタイトル行（header行）の真上のみだった。タイトル行は画面上の面積が小さく狙いにくいため、**プロジェクトのタイトル行と、その配下に表示されるコアアイテム（タスク）行の上にドロップしても、同じプロジェクトへ移動できる**ようにする。あわせて、ドラッグ中のハイライト（光る）範囲も、タイトル行だけでなく、**タイトル行から配下のコアアイテム行までの範囲全体**に拡大し、現在の移動先がどこかを視覚的に分かりやすくする。

## 2. 不変条件（09からの継承・本書での変更なし）

09 §2の不変条件（階層解釈の再利用、externalリンク非破壊、移動対象フィールドの限定、Y2再帰負荷モデルの非破壊、既存API経路の使用、自動統合の禁止）をすべてそのまま継承する。加えて本書独自の不変条件:

1. 移動先の値の決め方（09 §6、`computeDragMoveOutcome`）は**シグネチャ・ロジックとも一切変更しない**。item行にドロップされた場合も、最終的には既存のheader行ドロップと完全に同じ処理経路に合流させる
2. ドラッグ可能な対象（09 §4、`type: 'item'`の行のみ）は変更しない。今回拡大するのは**ドロップ可能範囲**のみ
3. バックエンドAPI・DBスキーマの変更は不要（今回はフロントエンドのみの変更）

## 3. サブプロジェクト境界の保証方針

全体一覧には入れ子のサブプロジェクトが存在しうる。あるコアアイテムは、それが直接属する直近の親プロジェクト/サブプロジェクトにのみ帰属すべきで、その祖先プロジェクトへ誤って移動してはならない。

`hierarchy.ts`の`buildHierarchicalList`が構築する`HierarchicalWrapper`は、既に以下を保持している（既存実装・無変更）:

- `item`行: `project: Item | null` — そのタスクが直接ぶら下がっている直近の親header（`projectContext`）。サブプロジェクトへ再帰する際にのみ更新されるため、祖先ではなく直近の親を正しく指す
- `header`行: `project: Item` — 自分自身

この既存フィールドから「そのwrapperが属するheader行のid（`header-${id}`形式）」を返す関数（以下`resolveGroupId`と呼ぶ）を導出するだけで、サブプロジェクト境界の正しさを**新しい親子解決ロジックを実装せずに**担保する。

- `type === 'header'` → `header-${wrapper.projectId}`
- `type === 'item'` → `wrapper.project` があれば `header-${wrapper.project.id}`、なければ`null`（ドロップ対象外）

## 4. DnD実装方式の拡張（09 §4の上書き）

09 §4「ドロップ可能: `type: 'header'` の行（`buildHierarchicalList` が生成する全てのプロジェクト／サブプロジェクト／work_package header）。1 header = 1 `useDroppable` ターゲット」を、以下のとおり拡張する:

- ドロップ可能: `type: 'header'` の行、および `type: 'item'` の行。item行は自分自身の`resolveGroupId`が指すheaderへの移動として扱う
- item行のdroppable idは`item-drop-${wrapper.id}`（header行の`header-${projectId}`と衝突しない別プレフィックス）
- item行のDOM refは、既存のdraggable用ref（`setDragRef`）とdroppable用ref（`setItemDropRef`）を同一ノードに適用する合成ref関数で結線する
- CSS `columnCount`による段組みレイアウト（09 §4継承）は本拡張でも変更なし。`groupId`はDOM順序・論理親子関係のみで決まり、ブラウザ側の視覚的な列割り当てに一切依存しない。ドロップ判定（`pointerWithin`、画面上の絶対矩形）も、視覚的にどの列にあってもDOM要素ごとのgroupIdで正しく判定される

## 5. ドロップ判定・ハイライトの拡張（09 §5の上書き）

09 §5「`over` が有効な header と一致する時のみ、その header 行だけをハイライトする」を、以下のとおり拡張する:

- `over`が有効なheader行、またはそのheaderに属するitem行のいずれかと一致する時、**そのheader行から配下のitem行までの範囲全体**をハイライトする（背景強調。「○○へ移動」ラベルはheader行のみに表示し、item行はハイライトのみで情報過多を避ける）
- dnd-kitの`useDroppable`の`isOver`は自要素がoverかどうかしか分からないため、「現在ドラッグでoverされている行が属するgroupId」を`OverviewBoard.tsx`側でstateとして持ち上げ（`onDragOver`ハンドラで`resolveGroupId`を解決してセット）、各行が`resolveGroupId(自分) === hoveredGroupId`を比較してハイライトの要否を決める
- `handleDragEnd`冒頭で`hoveredGroupId`をnullにリセットする
- ドロップ不可対象（09 §5の無効化条件: 子孫・テナント不一致・archived）は、groupId単位で事前計算したMapを参照し、header行・item行の両方が同じ禁止状態を参照する（矛盾したUXを避ける）

## 6. handleDragEndの変更

`over.id`から`resolveGroupId`相当の解決を行い、対応するheader行のwrapperを特定した上で、以降は既存コードパス（`computeDragMoveOutcome`呼び出し→`updateItem`→トースト→Undo、09 §6・§8・§9）へそのまま合流させる。`computeDragMoveOutcome`自体への変更はない。

## 7. 必須テスト

**サブプロジェクト境界:**
- [ ] root直下タスクの`groupId`がrootのheader idと一致する
- [ ] サブプロジェクトA配下タスクの`groupId`がAのheader idと一致し、親やAの兄弟サブプロジェクトのheader idにならない
- [ ] 3階層ネスト（root→mid→leaf）でleaf配下タスクの`groupId`がleafのheader idと一致し、root/midにならない

**ドロップ範囲拡大:**
- [ ] サブプロジェクトA配下のitem行へドロップすると、Aへ移動する（Aの親やAの兄弟にならない）
- [ ] item行ドロップとheader行ドロップで同じ移動先になる

**ハイライト範囲拡大:**
- [ ] ドラッグ中、対象groupのheader行・item行すべてに`data-drop-highlighted=true`が付く
- [ ] 対象外のgroupには`data-drop-highlighted`が付かない

**回帰（09からの継承）:**
- [ ] 既存の「多階層サブプロジェクトで、ドロップした階層だけが対象になる」テストが引き続きGreen
- [ ] 09 §12の全テスト項目（階層・データ保持・安全性・Beaver/Y2・UI）が引き続きGreen
- [ ] 10番（Beaverバッジ`overview-beaver-badge`）との共存に問題がない

CSS段組みの視覚的な折り返しを再現するブラウザ座標テストは追加しない（jsdomはCSS Multi-column非対応であり、DOM構造ベースのテストで正しさは既に担保されるため）。

## 8. 本番受け入れ確認（実装後に実施）

1. プロジェクトタイトル行だけでなく配下のコアアイテム行の上にドロップしても、正しいプロジェクトへ移動すること
2. ドラッグ中、対象プロジェクトのタイトル〜配下アイテム全体がハイライトされること
3. 入れ子のサブプロジェクトで、配下アイテム上でも正しいサブプロジェクトだけが対象になり、親や兄弟に誤爆しないこと
4. 段組みで折り返された状態でも正しく動作すること
5. R-155のドラッグ移動・R-156のBeaverバッジ表示が引き続き問題なく動作すること
