# 同形異義 UI レビュー（2026-08-19）

## 1. サマリ

対象コードと仕様を読み取り専用で照合し、同じ表示部品・短い数値ラベルが文脈によって異なる母集団や計算式を表す箇所を 9 件確認した。
最も混同リスクが高いのは、CapacityBar の「外部予定を含む／含まない」と「完了表示による母集団変更」、およびヘッダーの週負荷が現在の絞り込み済み ViewModel を母集団にしている点である。
また、「件」「合計」「日超過」「着手」は近い見た目でも、要判断・期限超過・フロー帯・最遅着手で起点と対象が異なる。
以下の「確認」はコードから確定できた事実、「推測」は実画面を操作せずコード構造から評価した混同可能性である。

## 3. 横断的な提案

1. 集計値の直前または直後に、母集団を表す1語を必須化する: `全体` / `案件` / `個人` / `会社`、必要時のみ `予定込` / `未完了`。表示面積を増やせない箇所は同語を tooltip に入れる。
2. CapacityBar 系へ共通の意味メタデータを渡す: `data-scope`、`data-numerator`、`data-denominator`（例: `project`, `tasks+external`, `personal-capacity`）。UI自動テストと tooltip 生成を同じ値から行う。
3. 「件」「合計」「日付」だけの裸ラベルを避け、最小接頭辞を統一する: `要判断`、`期限超過`、`案件合計`、`有効締切起点`。評価語を足さず事実の種類だけを示す。

## 4. 確認できなかった点・仮定

- 実ブラウザでの視認距離、レスポンシブ時の折返し、hover tooltip の既存有無は確認していない。リスク評価は React の描画構造と表示文字列からの推測を含む。
- `DashboardScreen` の `unifiedAllItems` は `useYoukanViewModel` のフィルタ済み各配列から作られるため、週負荷・要判断・超過分も現在スコープ／案件に追随すると判断した。ただし API 応答の実データと、全遷移経路での ViewModel 再生成は実行確認していない。
- 詳細モーダルの量感カレンダーは `externalEventsByDate` が渡される経路を確認したが、Google連携未設定時は当然外部予定0であり、見た目の差は発生しない。
- CapacityBar の分母は設定、休日、日別例外、会社別配分、チーム枠の条件分岐を持つ。全アカウント種別の実データで各分岐を再現してはいない。
- 全体一覧／状況把握には、今回の観点に直接該当する独立した「件数・時間の集計ヘッダー」はコード検索上限定的だった。全体一覧の `要判断`／`着手遅れ` はフィルタチップ状態が表示されるため、単独の発見行にはせず、ヘッダーバッジ・日付トークンとの差として記載した。
