# 番頭（外部AI）への依頼事項（2026-08-18、R-127〜R-134に伴う運用）

Youkan側の実装は完了・本番反映済み。以下はYoukan外（番頭のCron・Discord・音声登録）で担ってほしい運用。Youkanは新APIを増やしていないので、すべて既存 `GET /items?scope=aggregated`・`PATCH /items/{id}`・`POST /decision/{id}/resolve`・`POST /integrations/inbox`・`GET /quantity/week` で足りる。

## 1. 毎朝3件の「捌く」提示（R-127）
- キュー定義（Youkan `logic/reviewQueue.ts` と同一にする）: 未削除・未アーカイブ・`status ∉ {done, cancelled, someday}`・プロジェクト除外、かつ「有効締切（`due_date`/`prep_date` の早い方）＜今日」または「`status='pending'` かつ `review_date <= 今日`」。並び: 再確認到来 → 目安時間の短い順（未入力は最後）→ 有効締切の古い順
- 朝のfocus提示の直後に**先頭3件だけ**、番号回答形式で: 「①今日やる ②後日（+7日、変える場合は日付） ③断った」
- 回答→ `POST /decision/{id}/resolve` に `yes`／`later`（＋`prep_date`）／`no`。返事なしは翌日同じ3件を再提示。**勝手に既定処理しない**（音声＞Youkan、完了マークは本人確認後のみの合意を維持）
- 3日以上同じ3件が続いたら「先週から同じ3件を出しています」と事実だけ

## 2. 「後で」の問いかけ（R-134）
- 昼（12:00前後）に1回「後でと言っていた要判断、今は？」（件数は上記キューの件数）。褒め・励ましなし

## 3. 登録直後の一言（R-128）
- 音声登録で `POST /items` / `POST /integrations/inbox` を叩いた直後、レスポンスの `week_load.shortfall_minutes > 0` なら1問だけ: 「今週 Zh足りない。外す候補: A(8/22, 3h)／B(8/23, 4h)。どれか、または『そのまま』」（`week_load.over_candidates` をそのまま使う）。不足なしなら何も言わない
- 登録時に**目安時間を必ず聞く**（目安なしは着手日も週負荷も効かない）

## 4. 「断った」の一本化（R-127）
- 21:18日報の「今日は何を断りましたか？」で挙がった件は、Youkanに `status=cancelled` のアイテムを1件登録（`POST /integrations/inbox` → `PATCH` で status、`meta.declined=true`）。YoukanのKPI（今週断ったK件）はこれで一本化される

## 5. 「判断の言葉」の更新（R-127）
- 晴樹が集めている判断補助の短文（例「正しさより速さが正義」）は Youkan 個人設定「判断の言葉」（`users.preferences.judgment_phrases: string[]`）に保存。番頭が新しい言葉を聞き取ったら、既存のユーザー設定更新経路（`/user/profile` 系）で追記してよい

## 6. 番頭が読める数字（参考）
- 要判断件数・断った件数: `GET /items?scope=aggregated` から上記定義で算出
- 今週の枠／必要／不足: `GET /quantity/week`
- 最遅着手日: 当面Youkan画面のみ（PHP二重実装を避けるため未提供）

## 追記（2026-08-19、R-140 本番反映後）

Youkan 側に番頭向けAPIを新設した。**§1・§2・§6 は下記 1 本で置き換えられる**（キューの再実装は不要）。

- 認証: Youkan 個人設定「外部連携トークン」で発行した api_token を `Authorization: Bearer <token>` に付ける（`.env` のパスワード保持は不要に）。トークンは発行時に1回だけ表示
- `GET https://door-fujita.com/contents/Youkan/api/integrations/digest?date=YYYY-MM-DD&limit=3`
  - `review_queue: { total, items[] }` — 要判断キュー（F-52 と同一定義・同一並び。`items` は先頭 `limit` 件。各要素 `id,title,project_title,status,due_date,prep_date,review_date,estimated_minutes,overdue_days`）→ §1 の毎朝3件はこの `items` をそのまま提示
  - `week_load` — §3 と同じ `GET /quantity/week` の値
  - `uncontacted_overdue[]` — 案件別の未連絡遅延（`project_title,client_name,count,total_minutes,oldest_due_date`）→ 朝の「未連絡の遅延: ○○さん3件」
  - `declined_this_week` — 今週断った件数（§4 のKPI）
  - `focus[]` — 今日の focus 一覧
- 書き戻しは従来どおり `POST /decision/{id}/resolve`・`PATCH /items/{id}`・`POST /integrations/inbox`（R-141 で inbox 登録が本人の一覧に正しく出るようになった）
- 数字だけを返す。文言・評価語は番頭側で作る（褒め・励ましなし）
