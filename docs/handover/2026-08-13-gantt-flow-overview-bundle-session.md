## このセッションで得た運用上の学び（次回以降も有効）

- **指揮AIが直接編集したdocsファイルは即座にコミット・push**: 要望のR番号採番・SPEC追記・task.md追加は指揮AI自身が非コード文書として直接編集してよいが、コミット・pushを忘れたまま次のAgentを起動すると、Agent側のマージ時に指揮AIのローカル未コミット内容と衝突・消失するリスクがある（今回複数回発生。都度`git pull --rebase`で復旧したが、要望記録→即コミット・push→Agent起動、の順を徹底すべき）
- **worktree作成が稀に失敗する**: `"git could not be run to resolve it"`エラーで起動失敗するケースがあった。`git worktree unlock <path>` → `git worktree remove --force <path>` → `git worktree prune` で手動クリーンアップしてから再試行すると解決する
- **Agentがバックグラウンドプロセス完了待ちで停止することがある**: vitestのフルスイート実行等をバックグラウンドで回した際、その完了を待たずにAgentが停止してしまうケースが複数回あった。SendMessageで「バックグラウンド出力を直接確認して」「フォアグラウンドで再実行して」と具体的に指示すると再開する
- **インフラに近い変更は副作用を必ず確認する**: R-085でSQLiteをWALモード化した際、`-wal`/`-shm`補助ファイルが`upload.ps1`の除外パターン（`*.sqlite`のみ）や`.gitignore`（同）でカバーされておらず、本番DBを破損させるリスクに気づいた。レビュー時に指揮AI側から指摘して修正させた
- **大きな機能後退を伴う実装判断はAgent提案のまま承認しない**: R-092でAgentが「ガントと完全一致」を優先し、全体一覧の既存メニュー項目（いつかやる/アーカイブ等）を削除する実装を提出してきたが、レビューで気づいて発注者に確認し、既存項目を残す方針へ差し戻した
- **発注者の用語と実際の実装箇所が食い違うことがある**: R-088で発注者が「ガントチャート」と呼んでいた機能（空白部ダブルクリックでノード作成）は、コード調査の結果ガントには存在せず実際はフローチャート画面の機能だった。仕様化前にコード調査で実際の対象を特定することが重要
- **既存の共通ロジックを流用できないか必ず確認する**: R-076の依存関係順ソート（`sortWithDependencies`）はexportされていないだけで既に汎用ロジックだった（R-091）。R-089の目安時間二重PUT対策もR-085と同型のrefガードパターンで解決できた。車輪の再発明を避けられている
- **並列Agent間のファイル競合は事前の役割分担で回避**: 同じファイル（`FlowScreen.tsx`等）を複数Agentが触る場合、事前にプロンプトで「あなたのスコープはこの関数内に限定」と明示することで、実際のコード競合はほぼ発生しなかった。docsファイル（requests_log.md/task.md/SPEC）の末尾追記部分だけは頻繁にコンフリクトするため、マージ時は「両方残す」と毎回明示的に指示すること
